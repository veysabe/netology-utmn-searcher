# pdf-search

Поисковая система по текстовому содержимому PDF-документов с REST API.

Сервис сканирует заданные директории, извлекает текст из PDF, строит обратный
индекс и отдаёт результаты поиска по HTTP в формате JSON.

---

## 1. Концепция проекта

### 1.1. Проблема

В организациях накапливаются сотни PDF-документов (отчёты, методички,
договоры). Штатный поиск по содержимому в них отсутствует — найти документ
по ключевым словам можно только по названию файла.

### 1.2. Решение

Лёгкий self-hosted сервис без внешних зависимостей (только Python), который:

1. следит за списком директорий из конфигурации;
2. извлекает текст из PDF и нормализует его (нижний регистр, разбиение по `\w+`);
3. строит **обратный индекс** `слово → {id_документа: частота}`;
4. ранжирует документы по **TF-IDF**;
5. отдаёт результат по `GET /search`.

### 1.3. Требования

1. **HTTP-сервер с RESTful API** — закрыт
2. **Запрос может состоять из нескольких слов** — закрыт
3. **Папки для поиска в `config/config.yaml`** — закрыт
4. **Авто-доиндексация при старте** — закрыт
5. **Ранжирование на основе TF-IDF** — закрыт
6. **Без учёта регистра** — закрыт
7. **Максимум 10 результатов** — закрыт
8. **Чтение PDF через `pypdf`** — закрыт
9. **Без стемматизации и лемматизации** — закрыт

Формула ранжирования — см. [1.6](#16-формула-ранжирования).

### 1.4. Архитектура

```
config/config.yaml ──► config.config.load_config()
                              │
                              ▼
              document_reader.load_documents()   поиск *.pdf
                              │
                              ▼
                   index.index() ──► index_storage  кэш по mtime файла
                              │       (index_cache.json)
                              ▼
              structures.inverted_index + doc_lengths
                              │
                              ▼
              search.search()  TF-IDF + top-K (heapq.nlargest)
                              │
                              ▼
                  server.py  (http.server, stdlib)
                    ├── GET /search?q=
                    ├── GET /docs          Swagger UI
                    └── GET /openapi.yaml  спецификация
```

### 1.5. Ключевые решения

| Решение                              | Обоснование                                            |
|--------------------------------------|--------------------------------------------------------|
| `http.server` из stdlib              | Нулевые зависимости, достаточно для учебного кейса     |
| Обратный индекс                      | Поиск за O(запрос), а не перебором всех документов     |
| Кэш по `mtime`                       | Повторный запуск не переиндексирует неизменённые файлы |
| Глобальные словари в `structures.py` | Простота; осознанный долг |
| OpenAPI 3.0.3 + Swagger UI           | Контракт API и самопроверяемая документация            |

### 1.6. Формула ранжирования

```
tf(word, doc) = count / doc_length   (нормализованная частота)
idf(word) = log(N / df)
score(doc) = Σ  tf(word, doc) · idf(word)
             word∈query
```

Результат — не более 10 документов, отсортированных по убыванию `score(doc)`
через `heapq.nlargest`.

## 3. Наработки: решение кейсов

### Кейс 1. Как найти PDF и не сойти с ума

**Задача:** собрать список документов из нескольких директорий.

**Решение** — `document_reader.load_documents()`:

- пути из конфига разрешаются относительно корня проекта, поэтому
  `/data/docs` и `data/docs` работают одинаково;
- нераскрытую директорию не считаем ошибкой — просто пропускаем;
- расширение сравнивается без регистра (`.PDF` находится);
- вложенные папки не обходим — только «плоский» список, как в ТЗ;
- счётчик ID сквозной по всем директориям.

Закрыто 7 тестами: один PDF, не-PDF пропускается, верхний регистр,
несуществующая папка, очистка списка перед загрузкой, вложенность,
несколько директорий.

### Кейс 2. Медленная индексация и авто-доиндексация при старте

**Задача:** `pypdf` читает файл секундами; перезапуск сервиса был неприемлем.
Кроме того, при старте нужно проверять наличие новых файлов.

**Решение** — `index_storage`: снимок частот слово↔документ кладётся в
`index_cache.json`, ключ — путь файла, значение — `{mtime, words}`.
Если `mtime` не изменился, файл не парсится заново.

При старте `main.py` вызывает `load_documents()` (сбор списка PDF) и затем
`index.index()`, которая сравнивает каждый файл с кэшем. Новые и изменённые
файлы переиндексируются автоматически.

**Наработка/риск:** путь к кэшу относительный, поэтому файл создаётся
в директории запуска. Для продакшена нужно либо абсолютный путь из конфига,
либо переезд в MongoDB (этап 9).

### Кейс 3. «Иванов» и «иванов» — разные слова

**Задача:** поиск не находил документ, если регистр в запросе и в тексте
не совпадал.

**Решение:** и индексация, и запрос нормализуются через `.lower()`,
разбиение — единым `WORD_RE = re.compile(r"\w+")`, который вынесен в
`index.py` и переиспользуется в `search.py`. Один разделитель на оба конца
гарантирует, что индекс и запрос не разъедутся.

### Кейс 4. Сопоставимость документов разного объёма

**Задача:** сырая частота `count` в TF-IDF зависела от размера файла — в
большом документе слово встречалось чаще просто потому, что текста больше, и
такой документ обгонял короткий с плотным совпадением.

**Решение (PR #7):** частота нормализуется длиной документа —
`tf = count / doc_lengths[doc_id]`. Длина считается один раз при индексации
(`index.py`) и хранится в `structures.doc_lengths`. После этого score стал
сопоставим между документами разного объёма, и дополнительный ключ сортировки
по числу совпавших слов убрали: документ, покрывший больше слов запроса,
складывает больше положительных слагаемых и в сумме оказывается выше.

### Кейс 5. Отсутствие слова и вырожденный IDF

**Задача:** запрос может содержать слово, которого в корпусе нет вовсе, а
также слово, которое есть во всех документах.

**Решение:** перед обращением к индексу стоит `if not postings: continue`
— неизвестное слово просто не участвует в подсчёте, поэтому `df` никогда не
равен нулю и деления на ноль в `log(N / df)` не возникает.

При `df == N` получается `log(1) = 0`: слово присутствует во всём корпусе и не
помогает различать документы — оно обнуляется и фактически работает как
стоп-слово. Побочный эффект: в корпусе из одного документа IDF обнуляется для
всех слов, score становится `0.0`, но документ в выдачу всё равно попадает
(проверено).

### Кейс 6. Битый PDF ронял всю индексацию

**Задача:** один повреждённый файл останавливал запуск сервиса.

**Решение:** `try/except` на файл — документ пропускается с предупреждением,
остальной корпус индексируется.

### Кейс 7. Контракт API и его документация

**Задача:** разные участники должны были писать клиент и сервер по одному
и тому же договору.

**Решение:** `openapi.yaml` как источник истины + Swagger UI на `GET /docs`,
который сам же её и подгружает. Описание и реализация живут в одном репозитории
и не расходятся.

### Кейс 8. Не больше 10 результатов

**Задача:** по ТЗ сервис обязан возвращать максимум 10 самых релевантных
документов, а не весь список совпадений.

**Решение:** `search(query, limit=10)` берёт топ-K через
`heapq.nlargest(limit, scores, key=scores.get)`. Срез `[:10]` после полной
сортировки дал бы тот же результат, но стоил бы `O(N log N)` против
`O(N log K)` у `nlargest` — на большом корпусе разница заметна.

## 5. Быстрый старт

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Положите PDF в директорию из `config/config.yaml`:

```yaml
search_paths:
  - /data/docs
```

Запуск:

```bash
python main.py
```

Сервер поднимется на `http://127.0.0.1:8008`.

### Проверка

```bash
# интерактивная документация
open http://127.0.0.1:8008/docs

# поиск
curl "http://127.0.0.1:8008/search?q=отчёт"
```

Ответ:

```json
{
  "query": "отчёт",
  "results": [
    { "id": 1, "path": "/path/to/docs/example.pdf" }
  ]
}
```

### Тесты

```bash
python -m unittest discover -s tests -v
```

## 6. Эндпоинты

| Название действия    | Локейшн (URL)     | Тип запроса | Описание запроса и ответа           |
|----------------------|-------------------|-------------|-------------------------------------|
| Поиск документов     | `/search`         | `GET`       | Принимает `q`, возвращает документы |
| Swagger UI           | `/docs`           | `GET`       | Интерактивная документация API      |
| OpenAPI спецификация | `/openapi.yaml`   | `GET`       | YAML-спецификация OpenAPI 3.0.3     |
| Страница не найдена  | любой другой путь | `GET`       | Ошибка `404`                        |

Детали:

- **`GET /search?q=<запрос>`** — параметр `q` обязателен.
  Ответ `200`: `{"query": "...", "results": [{"id": 1, "path": "/path/to/file.pdf"}]}`.
  Ошибка `400`: `{"error": "empty query"}`, если `q` пустой.
- **`GET /docs`** — HTML-страница Swagger UI, код `200`.
- **`GET /openapi.yaml`** — спецификация API, код `200`.
- **Любой другой путь** — `404`: `{"error": "not found"}`.

Полная спецификация — [`openapi.yaml`](openapi.yaml).
